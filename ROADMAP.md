# AutoKeyPresser Roadmap

This is the queue for small, self-contained feature work. Every item is one pull
request, ships with its own tests, adds no runtime dependency, and leaves `.akp`
macros, `.akpt` themes, profiles, and saved settings readable by the version that
wrote them. Items are ordered by how many users hit the wall and how hard it stops
them, not by how easy it is to build, so the gaps everyone meets come before the
ones only sequence builders meet. The app stays local-only and offline by design:
nothing here adds accounts, telemetry, or network traffic beyond the existing
release check.

## Backlog

- [x] **Type text as a single action** — Keyboard mode sends one key per action, so typing a sentence, a URL, or a command line today means building a fifty-step sequence by hand. Add a Text mode beside Mouse and Keyboard that sends a whole printable string through `pyautogui.write`, stored as an optional `"text"` action in `autoclicker/config.py` and in profile actions, so existing profiles load unchanged. Files: `autoclicker/engine.py`, `autoclicker/app.py` (action card), `autoclicker/config.py`. Size: M. Tests: the engine types a multi-word string with punctuation once per action, a text action round-trips through a profile, and the saved config restores it on the next launch.
- [x] **Start delay before the first action** — Pressing Start means racing to the target window before the first click lands, and losing that race drops a real click somewhere else. Add a 0–30 second start delay with a visible countdown in the run plan, where Stop and F12 cancel it before any input is sent. Files: `autoclicker/engine.py` (`_run` pre-roll), `autoclicker/app.py` (run card and summary line), `autoclicker/config.py`. Size: S. Tests: no input is sent before the delay elapses, stopping during the countdown ends the run cleanly with no stray action, and the value persists to config.
- [x] **Edit and reorder the steps of a saved profile** — A profile can append an action but never correct one, so a mistyped key means deleting the profile and rebuilding it. Replace the read-only detail pane in the profile dialog with a step list that supports move up, move down, remove, and replace-selected-with-current-action. Files: `autoclicker/app.py` (`_open_profiles`), `autoclicker/profiles.py` (pure list helpers). Size: M. Tests: the helpers keep step order, a removed step is gone from disk after save, and replacing a step persists the new action.
- [x] **Give each sequence step its own delay** — Every step in a profile runs at the single global interval, so a sequence that should click, pause two seconds, then type has to be recorded as a macro instead. Add an optional `delay_ms` to profile actions with a delay field in the step editor; profiles written before this change keep the global interval and gain the field on their next save, so `profiles.json` needs no conversion step and stays loadable by older builds. Files: `autoclicker/engine.py` (per-action interval in `_next_interval`), `autoclicker/profiles.py`, `autoclicker/app.py`. Size: M. Tests: a profile without `delay_ms` still runs at the global interval, a profile with it waits the per-step value, and a save/load round trip preserves both.
- [x] **Stop automatically after a set duration** — Repeat-until-stopped has no brake, so an overnight run keeps pressing until somebody notices. Add a "Stop after" duration in the run plan that ends the run at its deadline and reports the limit in the status line, leaving the exact-count mode alone. Files: `autoclicker/engine.py` (deadline in `_run`), `autoclicker/app.py` (run card), `autoclicker/config.py`. Size: S. Tests: the engine stops at the deadline and still emits a final `done`, a manual stop before the deadline wins, and the setting round-trips through config.
- [x] **Warn at startup when input automation cannot work** — On a Wayland session, or on macOS without Accessibility permission, the app opens, accepts Start, and silently sends nothing. Add a startup preflight that checks the Linux session type and macOS accessibility trust through `ctypes` (standard library, no new dependency) and shows one message naming the documented fix. Files: `autoclicker/app.py` (startup path) plus a small pure helper beside `autoclicker/engine.py`. Size: S. Tests: X11 and Windows report supported, Wayland and untrusted macOS report unsupported, and each message names its fix.
- [ ] **Bind a profile to its own global hotkey** — Starting a favourite sequence costs opening the window, opening Profiles, and pressing Run sequence. Let a profile store a hotkey and register it with the existing pynput listener, with a per-profile message when the combination is already taken. Files: `autoclicker/app.py` (`_start_hotkey_listener`, profile dialog), `autoclicker/profiles.py`. Size: M. Tests: stored profile hotkeys map to registration calls, a conflicting binding is skipped with a readable message, and F12 still stops a profile run.
- [ ] **Turn a recorded macro into an editable profile sequence** — A recorded `.akp` is the fastest way to capture real input, but it is opaque: you cannot fix a step or mix it with hand-built actions. Add a "Convert to profile" button in Macro studio that folds key press/release pairs into hold actions, clicks into fixed-point actions, and reports how many scroll events it had to drop. Files: `autoclicker/macro.py` (pure conversion), `autoclicker/app.py` (macro bar), `autoclicker/profiles.py`. Size: M. Tests: a press/release pair becomes one hold action with the recorded duration, a click becomes a point action, and unsupported events are counted rather than silently discarded.
- [ ] **Add drag actions** — Sliders, window moves, and file drags cannot be expressed by clicking at a point, which pushes users into recording a whole macro for a two-step job. Add a Drag action type that presses at a start point, moves to an end point, and releases, available in the action card and as an optional `"drag"` profile step; profiles without it are unaffected. Files: `autoclicker/engine.py`, `autoclicker/app.py`, `autoclicker/profiles.py`. Size: M. Tests: the engine calls mouseDown, moveTo, and mouseUp in order with the configured coordinates and button, and a drag step round-trips through a profile.
- [ ] **Show which step is running** — During a sequence the status line only counts total actions, so a stalled five-step profile leaves you guessing where it stopped. Carry the step index and total in the engine's status message and show "Step 2 of 5" in the run plan while a sequence runs. Files: `autoclicker/engine.py` (`on_status` payload), `autoclicker/app.py` (`_poll_queue`, run card). Size: S. Tests: a multi-action run reports step and total, a single-action run reports step 1 of 1, and the final `done` message keeps its existing shape.
- [ ] **Keep the last recording across restarts** — An unsaved recording dies with the window, so Record, then close, quietly loses the take. Write the working macro to the config directory when recording stops, offer to restore it on the next launch, and remove the draft once it is saved or replaced. Files: `autoclicker/app.py` (macro studio), `autoclicker/config.py` (draft path). Size: S. Tests: the draft is written on stop, restored on startup, removed after a save, and never overwrites a `.akp` the user picked by name.
- [ ] **Warn when an imported theme is unreadable** — `.akpt` validation checks that colours are hex and the font size is sane, not that text is legible, so a shared theme with near-identical text and panel colours imports cleanly and leaves a window you cannot read. Add a contrast check on import that names the failing colour pair and asks before applying the theme. Files: `autoclicker/themes.py` (pure contrast helper), `autoclicker/app.py` (import path). Size: S. Tests: the WCAG ratio is correct for known colour pairs, all six built-in themes pass, and a low-contrast theme returns the offending pair.
- [ ] **Reset settings to defaults** — After trying hold mode, randomized timing, and a custom theme there is no way back to a clean slate short of deleting `~/.autokeypresser/config.json` by hand. Add a "Reset settings" button in Help that restores every key from `DEFAULTS`, reapplies the default theme, and leaves saved profiles and imported themes untouched. Files: `autoclicker/app.py`, `autoclicker/config.py`. Size: S. Tests: reset restores every default value, the active theme is reapplied, and profile and theme files on disk are left alone.

## Blocked

Valuable, but each one needs a runtime dependency, so none belongs in the daily queue
until adding one is a deliberate decision.

- **Wayland input injection.** Linux support requires an X11 session today. A Wayland
  backend needs a portal or compositor-specific path (`xdg-desktop-portal`
  RemoteDesktop, or `python-evdev`/`ydotool`), which is a new runtime dependency and a
  different permission model rather than a code change.
- **Minimize to tray.** Keeping the app off the taskbar with a tray icon needs
  `pystray` as a new runtime dependency.
- **Sign or verify shared `.akp` / `.akpt` files beyond the checksum.** Authenticity
  needs a cryptography dependency such as `cryptography`; today the SHA-256 checksum
  detects corruption, not intent.
